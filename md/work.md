# work.md

这份文件用于在另一台电脑、另一个会话或另一个 AI 助手接手时，快速理解这个项目怎么维护。

## 项目概况

- 项目路径：`A:\2026\作品集\4.13\网站`
- 项目类型：个人作品集网站，主要是静态前端页面。
- 主要语言：HTML、CSS、JavaScript。
- 运行方式：多数页面可以直接用浏览器打开对应的 `xxxindex.html` 文件。
- 修改主体不固定为某个历史文件。每次开始修改前，先检查网站根目录（不含 `Del/`、`Del/Temporary file/`、`node_modules/` 等备份、临时或依赖目录）中的 `数字+index.html`，以数字最大的文件作为当前最新主版本和本次修改主体；除非用户明确指定其他版本。当前扫描到的最新文件是 `652index.html`，但后续仍须重新扫描，不能把该编号永久写死。
- 依赖管理：npm，依赖记录在 `package.json` 和 `package-lock.json`。
- 目前 `package.json` 只有 `devDependencies`，没有配置 `scripts`，所以没有固定的 `npm run dev`、`npm run build`、`npm test` 命令。

## 主要目录

- `index.html`：早期或入口页面。
- 根目录中的 `数字+index.html`：按编号保存的连续版本页面，编号越大通常越新；默认以编号最大的文件作为修改主体，用户明确指定其他版本时除外。
- css/：样式文件。很多文件也按版本号命名，比如 research-chain-562.css、hardware-system-562.css。
- `js/`：脚本文件。很多文件也按版本号命名，比如 `research-chain-532.js`、`dev-flow-switcher-420.js`。
- `AIGC/`：项目图片、AIGC 素材和具体作品资源。
- `素材/`、`主界面/`、`GridScanDemo/`：页面会用到的素材或子项目资源。
- `md/`：历史聊天记录和任务记录，里面有大量之前的修改过程。
- `Del/Temporary file/`：临时文件、备份文件、方案预览文件可以放这里。
- `Del/`、`css/Backup/`、`js/Backup/`：历史备份或已移走文件，改动前要确认是否还被引用。
- `node_modules/`：本地依赖目录，不是网页运行必需内容，但 Playwright、Vite 等工具会用到。

## 临时测试文件归档

每次在 `网站/` 主文件夹产出的文件中，除本次及历史版本的 `index.html` / `数字+index.html` 和 `css/`、`js/` 文件夹内的文件外，其他临时测试文件（如测试脚本、截图、调试输出、临时预览文件）用完后都要移入 `Del/` 文件夹归档，不要留在主文件夹。归档前确认文件不再被正式页面或构建流程引用；不要覆盖 `Del/` 中的同名文件。

## 修改习惯

这个项目最重要的习惯：新需求通常新开一个编号版本。

推荐流程：

1. 先确认当前最新稳定版，比如 `548index.html`。
2. 复制成新编号，比如 `549index.html`。
3. 如果要改对应 CSS / JS，也复制成同编号文件，比如：
   - `css/research-chain-552.css`
   - `js/research-chain-552.js`
4. 把新 HTML 里的引用从旧编号切到新编号。
5. 只在新编号文件里修改。
6. 最后检查新文件没有残留不该残留的旧编号引用。

不要直接改旧稳定版，除非用户明确说“就改这个文件”。之前有过直接改旧版导致需要回退的情况，所以后续要更稳。

新增样式或脚本修改时，优先直接替换当前新版里的原有规则或原有逻辑，不要一层层在文件末尾追加覆盖。只有临时验证效果，或确实找不到稳定原规则时，才允许短期覆盖；确认方案后必须合并回对应规则，避免后面规则互相混淆。

## 编码注意事项

页面声明通常是 UTF-8。复制或批量替换时要保持 UTF-8，不要用系统默认中文编码写回文件。

历史上出现过问题：用错误编码复制 `417` 到 `418/419/420` 后，页面中文在浏览器里乱码。以后如果中文突然乱码，优先检查：

- HTML 是否声明 `<meta charset="UTF-8">`
- 文件本身是否真的是 UTF-8
- 复制/写入命令有没有用错编码

## 资源路径注意事项

- HTML 里的图片路径通常从项目根目录写，比如 `AIGC/绥远方志/硬件开发/xxx.png`。
- CSS 文件里写 `url(...)` 时，相对路径是从 `css/` 目录算的，必要时要写成 `../AIGC/...`。
- 历史上出现过柔焦背景路径被解析成 `css/AIGC/...` 的问题，导致图片背景看不到。
- 修改图片引用后，要检查文件是否真实存在。

常用检查：

```powershell
Test-Path -LiteralPath "AIGC\绥远方志\硬件开发\agent-dialogue.png"
```

## 设计和交互偏好

- 页面是作品集展示，视觉要精致，但不要把简单问题复杂化。

## 安全和文件规则

- 不要写入 API Key、Token、Cookie、密码、私钥。
- 不要提交或保存真实 `.env`、证书、密钥文件。
- 不要删除重要文件。清理旧文件前先放到 `Del/Temporary file/` 或 `Backup/`。
- 不要随便新增 npm 依赖。确实需要时，先说明为什么不能用现有方案。
- 不要大面积重构。能小改就小改，能局部解决就局部解决。
- 不要改与任务无关的页面、样式、脚本。
