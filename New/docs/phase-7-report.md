# PHASE 7 — 多设备展示与演示视频

日期：2026-10-25。

## 已完成

- 六种视口宽度 375 / 430 / 768 / 1024 / 1440 / 1920 的页面、导航、展示视频与滚动检查。
- 实际浏览器录制桌面 1440×900、平板 1024×768、手机 390×844。展示首页、经历概况、作品定位及桌面随页浏览／手机分层浏览。
- 三段无声 H.264 MP4，添加尺寸标注及淡入淡出；16.52 / 16.16 / 12.88 秒，约 824 / 595 / 321 KiB，总计约 1.70 MiB。
- 第 05 章由占位文案改为三个实际设备演示入口，WebP 静态封面合计约 83 KiB。点击入口才挂载播放器、请求视频；一次只打开一个，收起后卸载媒体。
- 复用自定义播放器，原作品视频行为不变；各设备演示可暂停、拖动进度，视频和控件宽度保持一致。

## 验证

- 生产构建与 TypeScript 通过。构建仍提示既有主包超过 500 kB，不隐瞒该项，列入 PHASE 8 性能优化。
- 3/3 真实录制流程通过；30/30 布局、媒体请求、播放、首页、导航、图谱、玻璃入场、霓虹灯回归通过。
- 已人工查看三端录制抽帧、桌面和手机展示区截图。
- 本机 Edge 自动化采样：开场玻璃开启最大帧间隔约 206 ms，关闭约 200 ms；图谱拖动中位约 5.6 ms，P95 约 5.7 ms。此为单次开发机观察，不是移动真机或跨浏览器性能保证，开场停顿仍需 PHASE 8 定位。

## 审查收尾

独立审查发现的两项问题已补回归：播放器样式不依赖图谱先挂载；打开播放器聚焦播放按钮，收起后焦点返回原设备入口。两个测试都先复现失败，再验证修复。

## 文件与复现

- 成品：assets/videos/showcase/{desktop,tablet,mobile}.mp4。
- 静态封面：assets/images/showcase/*.webp；保留原 PNG 便于重新导出。
- 录制：先构建，设置 PW_BROWSER_CHANNEL=msedge、RECORD_DEMOS=1，运行 js/tests/phase7-record.spec.ts。首次需要 Playwright FFmpeg。
- 包装：紧接录制运行 python/package-device-demos.py（使用系统 FFmpeg 和 Pillow）。常规测试会清理 test-results，故须在下一轮测试前包装。
- 常规验收：js/tests/showcase.spec.ts；录制测试默认跳过，避免每次回归重写媒体。

## 边界

这些视频是实际网页在模拟视口下的操作，不宣称已做物理手机／平板测试。PHASE 8 尚需跨浏览器、真机与最终性能验收；未执行发布。
