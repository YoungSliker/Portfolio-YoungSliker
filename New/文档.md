# 一、项目定位与目标

## 1.1 核心概念

本项目旨在将 YoungSliker 现有的个人作品集改造成一个以纵向滚动为主要交互方式的沉浸式作品网站。

网站不再以传统分类页面和静态作品网格为主要浏览方式，而是将个人介绍、成长经历和设计作品组织成一套连贯的交互叙事系统。

**核心概念：**

**SCROLL TO DISCOVER. CONNECT TO EXPLORE.**

通过滚动了解创作者，通过关系探索作品，通过项目详情理解完整的创作过程。

新版网站需要兼顾视觉表现力、作品信息的完整性、使用体验和后续维护能力。

其最终定位是一座可交互的个人创作档案馆，而不仅是一套展示动画。

## 1.2 核心目标

1. 建立具有辨识度的个人视觉品牌。
2. 让鼠标滚轮、触摸滑动成为主要阅读方式。
3. 实现高质量、可逆向播放的滚动叙事动画。
4. 将教育、工作、项目与获奖经历整合到统一时间轴。
5. 用可展开的关系图谱展示三大设计领域及其具体作品。
6. 点击作品后先显示简要介绍、负责内容和技能标签。
7. 保留现有完整案例，并建立可靠的项目跳转机制。
8. 实现桌面、平板、手机三种设备的独立响应式体验。
9. 制作三种设备的真实网站演示视频。
10. 保证网站可维护、可持续更新，并兼容 GitHub Pages。

## 1.3 设计与开发原则

**内容优先：** 视觉动画必须服务于作品表达，不能妨碍信息阅读。

**滚动优先：** 普通滚轮始终承担网页的纵向阅读，不应被图谱缩放操作意外拦截。

**交互真实：** 所有作品节点、时间轴和卡片都必须是实际可操作的网页组件，而不是依靠预渲染视频假装交互。

**分层探索：** 不在一个屏幕中展示全部作品，避免复杂关系图谱产生信息拥挤。

**资源复用：** 尽可能保留原有网站中的图片、视频、三维项目素材和完整案例内容。

**数据真实：** 项目完成时间、职责、使用技能等信息需要有内容依据。缺少信息时必须标记待确认。

**渐进开发：** 不直接推翻原站。先搭建新版原型，再逐步迁移和整合作品。

## 2.2 目标视觉风格

关键词：

**BOLD / EDITORIAL / EXPERIMENTAL / INTERACTIVE / MINIMAL**

整体采用大胆排版、克制色彩、空间化作品展示以及细腻的交互反馈。

不使用常见的 SaaS 仪表盘式布局，不将玻璃拟态、渐变发光和大量随机粒子作为主要设计语言。

## 2.3 色彩系统

| 名称 | HEX | 用途 |
|---|---|---|
| Primary Black | #111111 | 主标题、正文、深色场景 |
| Warm White | #FAF9F6 | 主要背景 |
| Accent Orange | #FF642D | 重点节点、导航、交互强调 |
| Light Gray | #E8E7E3 | 分隔线、背景结构 |
| Secondary Gray | #727272 | 辅助文字、时间标签 |
| Deep Black | #161616 | 深色章节或图谱强调 |

橙色作为核心品牌强调色。

不要求三个设计领域一定使用三种不同的鲜艳颜色。优先通过节点结构、图形形态和标签进行区分。

## 2.4 字体系统

封面使用极粗、紧凑的英文无衬线字体。

中文主体使用清晰、现代的无衬线字体。

建立四种文字层级：

- Display：超大封面标题。
- Heading：章节标题。
- Body：作品概况和经历正文。
- Metadata：年份、编号、技能标签及辅助说明。

字体选择应考虑中文与英文混排的协调性、跨系统显示和加载性能。

# 三、技术架构

## 3.1 推荐核心技术栈

| 技术 | 主要用途 | 优先级 |
|---|---|---|
| React | 页面组件和交互状态 | 必选 |
| TypeScript | 作品数据与类型约束 | 必选 |
| Vite | 开发、资源打包与构建 | 必选 |
| GSAP | 动画时间线与元素过渡 | 必选 |
| GSAP ScrollTrigger | 滚动叙事 | 必选 |
| @gsap/react | React 动画生命周期管理 | 推荐 |
| @xyflow/react | 交互式作品关系图谱 | 首选 |
| CSS Grid / Flexbox | 响应式布局 | 必选 |
| Playwright | 自动化测试和网页录制 | 必选 |
| FFmpeg | 视频转码、裁切与合成 | 视频阶段按需使用 |

可选技术：

- D3：关系图布局计算或力导向效果。
- Cytoscape.js：React Flow 不适合最终图谱形态时的备选。
- Lenis：原生滚动不满足视觉要求时使用。
- Three.js：确实需要三维视觉对象时使用。
- Remotion 或其他视频合成工具：根据后期视频要求选择。

**不得为了使用某个框架而改变预定交互。**

## 3.2 图谱技术决策

第一版优先使用 React Flow，但必须先完成图谱技术验证。

原因：

- 支持节点与连线。
- 支持自定义节点组件。
- 支持画布移动与缩放。
- 方便与 React 状态管理集成。
- 能够实现选中、展开、聚焦和详情卡片。

但 React Flow 本身更偏向节点编辑器。最终图谱需要的是具有艺术表现力的关系网络，不应直接保留其默认流程图外观。

因此需要：

1. 自定义节点和连线外观。
2. 使用适合视觉构图的布局坐标。
3. 加入平滑布局动画。
4. 控制不同层级的显示与隐藏。
5. 限制或禁用编辑器式的节点拖动。
6. 在技术原型中验证复杂度和视觉效果。

如果实际效果过于机械，允许引入 D3 进行图谱坐标布局，或评估其他图库。

该决策必须在作品图谱原型阶段完成，而不是在全部项目接入后再更换。

## 3.3 滚动技术

采用 GSAP ScrollTrigger 统一管理关键章节动画。

使用：

- `scrub`：让动画进度跟随滚动。
- `pin`：短暂固定需要重点展示的场景。
- `matchMedia`：为不同视口配置动画。
- `refresh`：在布局、媒体尺寸变化后更新触发位置。

关键要求：

- 不要嵌套大量全屏固定滚动容器。
- 不要让多个独立动画系统争夺相同元素。
- 页面滚动位置应能够正确恢复。
- 向上滚动应可以反向查看对应动画。
- 用户快速滚动时不能产生持续卡死或闪烁。

初始版本优先原生滚动，不默认引入 Lenis。

## 3.4 视频制作技术

本项目不指定 HyperFrames 或其他特定视频框架。

视频制作以最终视觉质量、可重复制作及内容真实性为标准。

建议流程：

真实网页交互 → 自动化操作与录制 → 视频剪辑和视觉包装 → 成品导出。

录制可以使用 Playwright 或专业录屏工具。

剪辑、设备外框、文字包装与编码可以使用 FFmpeg、Remotion 或其他合适工具。

**视频只作为网页展示与作品宣传素材，不能代替网站实际交互。**

## 5.1 核心构图

页面占满首屏。

顶部左侧：

**YOUNGSLIKER®**

顶部右侧导航：

**ABOUT / JOURNEY / WORKS / CONTACT**

中央巨型标题：

**YOUNGSLIKER**

副标题：

**AI × CREATIVE × INTERACTION**

中文描述：

探索人工智能、数字体验与视觉传播的边界。

英文描述：

*Exploring the boundaries of AI, digital experiences and visual communication.*

底部显示：

**SCROLL TO EXPLORE ↓**

## 5.2 漂浮作品卡片

参考 Numerous 式封面，在大标题周围设置 4–6 张不规则排列的视觉卡片。

建议使用：

- 绥远方志。
- 矿山*生态。
- 微元灵溯。
- 新媒体交互作品。
- 库伦荞麦品牌设计。
- 视觉传达代表作品。

每张卡片可以具有：

- 不同的尺寸。
- 轻微倾斜角度。
- 柔和阴影。
- 小幅度鼠标响应。
- 与滚动相关的位移和旋转。

不要求每张卡片都能点击，但如果有明确的点击反馈，就必须能打开对应项目。

## 5.3 封面滚动动画

初始状态：

- 显示巨型标题。
- 作品卡片分散在标题四周。
- 页面保持简洁。
- 鼠标滚动提示可见。

开始滚动：

- 文字缓慢放大。
- 不同卡片以不同速度发生视差。
- 少量视觉元素从画面外进入或离开。
- 背景图形产生轻微空间变化。

继续滚动：

- 标题向边缘离开。
- 作品卡片逐渐散开。
- 个人介绍文字出现。
- 背景平滑过渡到下一章节。

不使用突然的黑屏或无内容过渡。

桌面端可以使用适度的固定视口滚动叙事，手机端应明显缩短动画距离。

# 八、SECTION 04：作品关系图谱

## 8.1 模块定位

该模块是新版网站最重要的交互部分。

目标不是模拟一张平面思维导图，而是构建一个具有设计感的可探索作品网络。

用户能够直观看到：

- 主要设计领域。
- 每个领域下的具体方向。
- 各个方向中的作品。
- 作品名称和完成时间。
- 作品的负责内容与技能。
- 完整案例入口。

## 8.2 图谱层级

**LEVEL 0 — 中心**

YOUNGSLIKER

**LEVEL 1 — 三大领域**

AIGC 设计。

数字体验设计。

视觉传达设计。

**LEVEL 2 — 代表作品或子分类**

例如：

- 绥远方志。
- 矿山。
- 微元灵溯。
- 新媒体艺术设计。
- APP 设计。
- 品牌设计。
- 版面设计。
- LOGO 设计。

**LEVEL 3 — 具体项目**

以作品名和完成时间作为主要信息。

AIGC 的三个代表性项目直接作为强调节点，不强制增加一层无意义分类。

## 8.3 AIGC 分支

**AIGC DESIGN**

重点项目：

- 绥远方志。
- 矿山*生态。
- 微元灵溯。

三个重点作品使用较大的节点与视觉缩略图。

另外增加：

**AIGC EXPERIMENTS**

用于收纳原有背景墙中的其他 AIGC 实验项目。

可按实际内容组织：

**生成影像与叙事**

天堂快递站、蛇祖漫剧、老物件《伞下》等。

**空间、视觉与 IP**

元宇宙空间设计、白桦林主题餐厅设计、黄河文化符号 IP 等。

**AI 应用与研究**

Stable Diffusion 经验分享、智慧助老、AI 信息可视化、科普教程等。

这些作品名称来自已有素材目录，但是否作为独立项目及其完成时间，需要进一步核对。

## 8.4 数字体验设计分支

**DIGITAL EXPERIENCE DESIGN**

分为两大节点：

**A. NEW MEDIA ART**

已有项目包括：

- Kinect 表情交互。
- Kinect 手势水交互。
- Kinect 粒子雨交互。
- Leap 手势文物交互。
- 昆虫音画动态海报。

- 舞动的植物 — 半日花。
- 核战风险 — 给和平机会。
- 海报版式练习。
- 新闻长图设计。
- 呼市记忆相关设计。

**C. LOGO DESIGN**

建议包括：

- 创意归绥。
- 如意蒙银。
- 美季酒店。
- 青城构造。
- 西贝莜面。
- 自由呼市。
- 其他 LOGO 作品。

LOGO 类节点数量较多，不应全部在初始状态下显示。

默认展示精选节点，并提供展开全部功能。

## 8.6 图谱视觉要求

图谱整体采用中心辐射式布局。

中心节点连接三个主要方向。

主领域向外展开次级分支。

子分类连接具体作品。

连接线应体现层级关系，但不造成过多视觉噪声。

建议节点样式：

| 类型 | 视觉表现 |
|---|---|
| 中心节点 | 最大视觉标识 |
| 主分类 | 大号文字与明显的连接关系 |
| 子分类 | 中型文字节点 |
| 作品 | 小型节点、作品名与年份 |

图谱要有适度的有机空间感，但布局保持稳定。

不允许用户每次刷新后都面对完全不同的随机节点位置。

## 8.7 两种浏览模式

### STORY MODE — 自动叙事

该模式由页面滚动控制。

进入图谱后，画面依次展示：

**STAGE 1**

完整作品宇宙。

中心节点和三大领域出现。

**STAGE 2**

聚焦 AIGC 设计。

展开代表作品与实验方向。

**STAGE 3**

聚焦数字体验设计。

展开新媒体艺术与 APP 两个方向。

**STAGE 4**

聚焦视觉传达设计。

展开品牌、版面和 LOGO 三大方向。

**STAGE 5**

恢复完整图谱。

显示自由探索提示。

用户向上滚动时，应能够回到前面的阶段。

### EXPLORE MODE — 自由探索

点击 `EXPLORE THE UNIVERSE` 后进入手动探索。

允许：

- 点击主分类。
- 展开子分类。
- 聚焦作品。
- 拖动画布。
- 使用缩放按钮。
- 点击作品查看详情。
- 返回上一级。
- 重置图谱。
- 退出探索模式。

**核心规则：** 在手动探索模式中，禁止故事滚动动画自动覆盖用户当前的选中节点和视口位置。

退出后重新同步当前滚动位置，恢复对应的故事阶段。

## 8.8 滚轮冲突规则

这是开发中的强制验收项目。

**默认普通滚轮必须继续使网页上下滚动。**

React Flow 需要关闭默认滚轮缩放与滚轮平移。

图谱可以通过以下方式缩放：

- 图谱控制按钮。
- 桌面端特定修饰键组合。
- 平板和手机端双指缩放。

不能出现鼠标移动到图谱区域后，整个页面无法继续向下滚动的问题。

必要时设置清晰的 `CONTINUE SCROLLING` 或 `EXIT EXPLORE` 按钮。

## 8.9 图谱状态管理

至少维护：

- 当前模式：story / explore。
- 当前主要分类。
- 当前子分类。
- 当前选中作品 ID。
- 已展开的节点。
- 详情面板状态。
- 当前滚动叙事阶段。
- 当前画布视口状态。

图谱状态应集中管理。

不要让滚动组件、节点组件和详情卡片分别建立互相冲突的独立状态。

## 8.10 手机端图谱

手机端不直接等比例缩小桌面关系图。

采用分层聚焦的移动端图谱。

初始状态显示中心和三个主要分类。

点击主分类后，视口自动聚焦。

进一步点击子分类展开作品。

只显示当前层级需要的主要内容，降低节点密度。

必要时提供辅助的层级列表，用于快速跳转具体作品。

# 九、作品详情卡片

## 9.1 交互流程

用户点击作品名称或节点后：

1. 图谱保持当前选择。
2. 当前节点高亮。

6. 通过明确按钮进入完整项目。

禁止点击节点后直接产生无法返回的全屏跳转。

## 9.2 卡片内容

必须包含：

**项目标题**

中文名称，必要时增加英文名称。

**完成时间**

年份或准确日期。

**所属分类**

AIGC / 新媒体艺术 / APP / 品牌 / 版面 / LOGO。

**作品概况**

约 60–120 个中文字符。

说明项目是什么、解决什么问题或表达什么概念。

**我负责的内容**

例如：

AI 生成 / 代码 / 三维模型 / 视觉设计 / 动效 / 剪辑 / 交互原型 / 信息架构 / 品牌视觉。

**使用的技能**

例如：

AIGC 设计 / 新媒体艺术设计 / 交互体验与场景叙事 / 用户体验设计 / 人工智能与创新设计 / 影视视听语言 / 版面与视知觉原理。

**完整作品入口**

`VIEW FULL PROJECT ↗`

## 9.3 示例：绥远方志

**绥远方志**

AIGC / 沉浸式历史体验

作品概况：

围绕呼和浩特城市历史与地方文化，探索生成式人工智能、数字场景和交互叙事相结合的沉浸式体验方式。

建议职责标签：

三维场景 / AI 生成 / 交互逻辑 / 视觉叙事 / 技术整合。

建议技能标签：

AIGC 设计 / 沉浸式体验设计 / 交互体验与场景叙事 / 人工智能与创新设计。

以上为待核对的展示文案，不能在未经确认时当作已验证的个人职责。

## 9.4 卡片布局

桌面端：

右侧抽屉式卡片，宽度约 380–440px。

平板端：

根据屏幕方向使用侧面板或居中卡片。

手机端：

底部弹出面板。

支持关闭、内部滚动与安全区域适配。

点击完整案例后，应能正常访问原有项目内容。

# 十、旧作品页面保留与迁移

## 10.1 核心原则

**新首页是作品索引，旧项目详情是深度内容。**

优先保留现有的完整案例。

特别是 AIGC 三个重点作品，应尽量复用已有项目页面、图像、视频和交互功能。

## 10.2 迁移策略

执行正式开发之前必须：

1. 检查仓库完整文件结构。
2. 确定原网站入口。
3. 确定旧页面内部导航方法。
4. 找到项目打开和关闭逻辑。
5. 记录各类作品资源路径。
6. 检查大型媒体文件及其引用关系。
7. 确认 GitHub Pages 当前构建方式。

新代码应优先在隔离的目录和独立分支开发。

不得未经检查直接覆盖原 `index.html` 并删除旧资源。

## 10.3 项目深链接

新网站的作品节点必须能形成可分享的地址。

推荐使用项目唯一 ID 与 URL 参数。

例如：

`?work=suiyuan-fangzhi`

通过这个地址进入时：

- 自动打开新版首页。
- 定位到作品图谱。
- 聚焦对应作品。
- 打开作品概况卡片。

完整项目页面需要有独立可访问的稳定地址。

如果原有项目只能通过 JavaScript 内部状态打开，必须增加兼容跳转机制。

不能把用户导航到错误分类或首页就视为完成。

## 10.4 GitHub Pages 兼容

现有站点部署在仓库子路径下。

Vite 正式构建必须正确配置：

`base: '/Portfolio-YoungSliker/'`

项目图片、视频、脚本和详情路径必须与部署地址相容。

不能只在本地根路径下测试成功，就直接认定 GitHub Pages 部署没有问题。

- 16:9。

8. 结束画面。

## 11.3 Tablet Video

建议：

- 适合平板的横屏或竖屏比例。
- 20–30 秒。

演示内容：

- 平板端封面。
- 滑动页面。
- 时间轴布局。
- 图谱的触摸交互。
- 作品卡片。

## 11.4 Mobile Video

建议：

- 1080×1920。
- 9:16。
- 20–30 秒。

演示内容：

- 手机封面。
- 纵向滑动。
- 单列时间轴。
- 图谱分类展开。
- 底部项目详情。
- 项目跳转。

## 11.5 网站内的设备展示

可制作一个简洁的三设备展示章节。

主标题：

**ONE CREATIVE UNIVERSE. EVERY SCREEN.**

桌面、平板和手机以不同的布局出现在页面中。

滚动时依次强调不同设备。

各设备画面使用真实网站录屏，或在性能受限的情况下使用静态预览。

不要求视频自动同时播放。

确保设备展示章节不会影响前面作品图谱的流畅程度。

## 11.6 视频制作流程

1. 网站主体功能完成。
2. 使用 Playwright 或录屏工具操作真实网站。
3. 录制各设备视口。
4. 检查录像分辨率和内容。
5. 按需使用 FFmpeg、视频剪辑工具或适当的视频框架包装。
6. 添加简洁的标题与转场。
7. 导出各设备视频。
8. 压缩适合网站播放的版本。

录屏时必须使用可重复的交互脚本，便于未来网站更新后重新制作视频。

# 十二、响应式设计

## 12.1 主要适配范围

Mobile：小于 768px。

Tablet：768–1199px。

Desktop：1200px 及以上。

实际布局可以使用容器查询进一步调整。

## 12.2 电脑端

- 完整的大标题封面。
- 丰富的漂浮作品贴纸。
- 双栏经历时间轴。
- 完整关系图谱。
- 右侧作品详情抽屉。
- 丰富但受控的滚动动画。

## 12.3 平板端

- 减少漂浮卡片。
- 调整文字比例。
- 压缩时间轴空间。
- 图谱根据当前分支自动适配视口。
- 支持触摸和双指缩放。

## 12.4 手机端

- 巨型标题自动换行。
- 封面只保留最重要的视觉卡片。
- 关于我采用单栏结构。
- 经历变成左侧细线的单列时间轴。
- 图谱采用分层聚焦。
- 项目详情使用底部弹出面板。
- 缩短复杂滚动动画。
- 避免难以关闭的全屏固定场景。

## 12.5 降级规则

对性能较低的设备：

- 减少同时运动的元素。
- 减少视频自动播放。
- 关闭不必要的高频视觉效果。
- 使用静态图片替代重型动效。
- 确保作品内容仍可完整浏览。

支持 `prefers-reduced-motion`，并确保动画关闭时不会出现内容缺失。

# 十三、作品数据结构

## 13.1 统一管理

所有项目数据应与 UI 组件分离。

建议每个作品至少包含：

- `id`：项目唯一标识。
- `title`：中文名称。
- `titleEn`：英文名称，可选。
- `category`：一级分类。
- `subcategory`：二级分类。
- `year`：完成年份，未知时为空。
- `dateLabel`：精确日期，可选。
- `summary`：作品概况。
- `responsibilities`：本人负责内容。
- `skills`：技能词汇。
- `cover`：作品封面路径。
- `previewVideo`：预览视频，可选。
- `detailUrl`：完整案例地址。
- `status`：已发布、待补充、待审核。
- `featured`：是否为重点项目。

不将所有信息硬编码在关系图谱的节点组件中。

## 13.2 图谱数据

图谱节点和作品数据分开维护。

节点分为：

- Root。
- Category。
- Subcategory。
- Work。

节点引用作品 ID。

不同作品可以关联同一个技能，但不需要在图谱中重复生成作品节点。

## 13.3 项目信息真实性

没有准确年份时，不要编造日期。

没有确认个人职责时，使用待审核字段。

没有完整案例时，明确标记资源状态。

不得将尚未实现的交互标注为已经完成的功能。

# 十七、性能与质量要求

## 17.1 性能

- 首屏优先加载必要资源。
- 图片和视频按需加载。
- 大型项目详情不要全部预加载。
- 图谱尽量只渲染当前需要的节点。
- 不在滚动事件中频繁重新生成布局。
- 避免 React 无意义重复渲染。
- 视频离开视口时停止或暂停播放。
- 手机端减少高成本动画。

建议以 LCP、INP、CLS 和实际滚动流畅度作为主要性能指标。

## 17.2 可用性

- 所有按钮具有明确反馈。
- 作品节点可通过键盘访问。
- 图谱提供非画布式的辅助列表导航。
- 作品详情面板支持关闭。
- 任何交互模式都有明确退出方式。
- 不存在必须使用鼠标 hover 才能获取的重要内容。
- 减少动态效果模式保持信息完整。

## 17.3 信息质量

- 所有正式作品名称需要核对。
- 完成时间不能猜测。
- 本人负责内容需要核实。
- 技能标签保持统一。
- 奖项与经历不应夸大。
- 没有实际内容的项目不能伪装成完整案例。
